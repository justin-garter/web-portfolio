Home Lab Environment

My personal infrastructure is one Proxmox machine and two Raspberry Pis at my place. Proxmox runs the firewall, a Jellyfin media server and a modded Minecraft server for about ten friends. One Pi serves this website and the other holds the backups. It's segmented into five VLANs behind an OPNsense firewall I run as a virtual machine, backed up nightly, and every host but the firewall is defined in Ansible so I can rebuild it somewhere else. The firewall comes back from a tested backup.

02

Why It's Built This Way

Router can't do VLANsPossible move Jul 2027

I moved into a place with roommates in September 2026. The house router belongs to one of them, and it can't do VLANs. I wasn't going to replace someone else's router, so the segmentation had to live behind it.

The answer was to make the firewall a virtual machine. OPNsense runs on Proxmox and treats the house network as its internet connection. Everything I own sits behind it on a managed switch, and the house router only forwards two ports to it.

The second constraint is that I might move again in July 2027. So nothing here is left to memory. Every host except the firewall is an Ansible playbook, and the firewall comes back from a backup I've already test-restored. The plan for moving is a playbook run and a restore, not a rebuild from memory.

03

The Network

6 segments2 public ports

Each segment exists for one reason, and the firewall only allows what that reason needs. My desktop is the one place that can reach everything. The management network can reach the servers for SSH and monitoring, and nothing else. The server and DMZ networks get the internet and their own DNS, and they can't start a connection to any other private network.

Nothing in the lab can start a connection to the house network either. That one's on purpose: the house network has devices on it I don't control, so the lab treats it as untrusted in both directions.

40 DMZ 10.10.40.0/24 Web Pi 10.10.40.10, vm-minecraft 10.10.40.20 Internet and its own gateway's DNS only. Static addressing, no DHCP
99 WAN transit 192.168.0.0/24 House network. OPNsense WAN 192.168.0.254 Nothing in the lab may start a connection to the house network

The internet reaches exactly two things. The website is HTTPS through Cloudflare only, and the firewall drops anything on 443 that isn't from Cloudflare's published ranges. Minecraft is port 25565, open to anyone, on a VM in the DMZ. Both public hosts are kept off my Tailscale network, so a compromise of either one doesn't hand over a way into the rest.

Every host also runs its own default-deny nftables firewall. If the gateway rules were ever wrong, each host still only answers what it's meant to.

04

What Runs on It

3 services

This website runs on a Raspberry Pi in the DMZ. It has its own write-up: Self-Hosted Personal Portfolio.

Minecraft runs on a 10 GB Debian VM in the DMZ. It hosts two modpacks on different Java versions, and a switch command swaps which one is live. I moved it off a Raspberry Pi, which had been capping it at a 6 GB heap. On the VM, the Crazy Craft pack starts in 69 seconds instead of over 200. Players connect to justingarter.com with no port, through an SRV record.

Jellyfin runs in Docker on a VM in the servers network. My TV and phone are on the house network, so they reach it through a port forward on the firewall that only answers on 8096 and only from the house network. It transcodes on the CPU. The GPU stays as Proxmox's local display on purpose, because the physical console is my way back in if the network breaks.

05

Backups and Recovery

Nightly, append-onlyRestore tested

Every night Proxmox backs up every VM and its own configuration into restic on a separate Raspberry Pi. The repository is served append-only, so Proxmox can add backups but can't delete or overwrite them. Only the Pi prunes, once a week.

The Minecraft VM backs up its own worlds at 02:15, before the 03:00 full backup. That way every nightly VM backup holds a clean copy of the worlds, not files caught mid-write. The world backups are uncompressed on purpose, so restic only stores the parts that changed.

Every night Sundays only

I tested the restore before calling it done. I restored the firewall VM from backup to a spare ID, booted it, and its configuration matched the original exactly.

The out-of-band path got the same treatment. Proxmox has a second connection over Wi-Fi to the house guest network, with Tailscale bound to it. From my phone on cellular, I shut down the firewall VM, confirmed I could still reach Proxmox, and started the firewall again. A heartbeat to healthchecks.io emails me if that path ever drops.

06

Infrastructure as Code

20 roles2 repos

The lab is two Git repos. One holds the website server's playbook. The other holds 12 Ansible roles for everything else: the Proxmox host, both VMs, the backup Pi, Docker, Jellyfin, Minecraft, backups, monitoring and the traffic report. Secrets live in an encrypted vault. The firewall is the one exception: its configuration comes back from backup rather than from a role.

The test I trust is the second run. A role is done when running it against a live host reports zero changes. That's how I brought the Proxmox host itself under Ansible: I wrote the role to match the running machine, then ran it until it reported nothing to change. The network config is in the role too, but it's never applied by a routine run, because a bad push there takes everything down.

07

What Went Wrong

2 incidents

My phone and TV couldn't load Jellyfin. After I opened Jellyfin to the house network, my phone timed out while the firewall logs showed the traffic arriving and being passed. The VM wasn't dropping it either. The cause was an OPNsense default: on an interface with a gateway, it sends replies back through that gateway instead of straight to the client. Replies went to the house router, which dropped them. One global setting fixed it, and I took a snapshot of the firewall first so I could undo it.

Scanners were hammering the website. The first traffic report showed about 1,250 requests for paths that don't exist, like /config.json and /docker-compose.yml, in 37 hours. My fail2ban jail could see them but couldn't block them, because behind Cloudflare every request comes from a Cloudflare address. I moved the blocking to a Cloudflare WAF rule kept in the repo and retired the jail. In the hours after, scanner requests reaching the server dropped to zero.

Outcome

Everything I host runs behind a firewall I control, on a network I don't own. Each service is in the segment it belongs in, every host but the firewall is a playbook, and the backups have been restored, not just taken. It isn't production, and a few things are still untested. But the parts that are done have been checked by trying them, which is the standard I hold the rest to.
